Help

Setup guide for Jira administrators. Last updated: 24 October 2026.

In short: open Jira settings, then Apps, then Portal Request View Plus. Pick a service project and a request type, switch on what customers should see, and save. Nothing is shown anywhere until you switch a request type on.

Set up in five minutes

  1. Open the settings page. In Jira, select the cog, then Apps, then Portal Request View Plus in the left sidebar. You need to be a Jira administrator.
  2. Pick a request type. Choose the service project, then the request type. Settings are kept per request type.
  3. Switch the panel on. Turn on Show the panel on this request type, then the parts you want: assignee, service targets, linked requests and extra fields.
  4. Save. Customers see the change within about five minutes.
  5. Optional: copy it across. Apply to all request types writes the same settings to every request type in the project. Request types you add later start switched off.

What each part shows

  • Who is working on it: the assignee's display name, or "Not assigned yet". Never an email address or account ID.
  • Service targets: each SLA as On track, Due soon, Overdue, On hold, Met or Missed, with time left, an optional progress bar and due time, and an optional goal. You can show only some SLAs and rename them, for example "Time to resolution - P1 internal = Resolution target".
  • Linked requests: key, summary, status and the relationship, for example "is blocked by". By default only issues in the same service project are shown. Turning that off shows linked issues from other projects, such as a development board, so use it only if customers should see them.
  • Extra fields: read-only fields you pick, with your own names, grouped under your own headings, in your order.

Show it to some customers only

Every part has an Only for these organizations list, and the panel as a whole has Who sees the panel. These use your Jira Service Management customer organizations.

  • Empty means everyone. With no organization selected, everyone who can open the request sees it.
  • Pick organizations to narrow it. A customer sees that part only if they belong to at least one of the selected organizations. Example: show service targets only to your premium-plan organization, or pilot the whole panel with one friendly customer first.
  • Agents always see everything, so you can preview the customer view from the help centre.
  • If membership cannot be checked, restricted parts are hidden. Parts without a restriction still show.

Organizations are managed in your service project under Customers. After an upgrade that added this feature, a site administrator must accept the app's new permission (reading customer organizations) under Apps, Manage apps before the lists load.

Assets objects and other app-specific fieldsNothing. The picker marks these "May show blank".
SLA fieldsUse the Service targets switch instead

Never shown, whatever the settings: comments, worklogs, time tracking, attachments, reporter, creator, watchers, votes, security level, sub-tasks and parent. These are blocked in the app's code, not just hidden in the settings page.

Troubleshooting

  • The panel does not appear at all. Check that the request type is switched on, that Who sees the panel includes the customer's organization or is empty, and that the customer can open the request. Logged-out visitors never see the panel.
  • A "Request details" heading appears with nothing under it. Jira draws the heading for every request type once the app is installed. Switch the panel on for all request types (use Apply to all request types) so every request shows content.
  • The panel is empty on every request type, even when switched on. The app's own user may not be able to read the project. In the project's permission scheme, Browse Projects must include the project role atlassian-addons-project-access. Default schemes include it.
  • A field shows nothing. It is empty on that request, or it is a type marked "May show blank" in the picker.
  • The organization lists say they could not be loaded. Accept the app's new permission under Apps, Manage apps, then reload the settings page.
  • The settings page says the licence is not active. Customers do not see the panel until the subscription is active again. Your settings are kept.
